# What is missing

What is ready, what is not, and how the backlog is covered. "Ready" means built, tested in jsdom and documented. **Nothing here has been seen in a browser**, and no route of the product is built: every screen is an example with example data.

Priority is the author's proposal, taken from the order of the backlog (dependencies) and from what blocks the pilot.

## Components that do not exist

| Missing | Used for | Until then | Source |
|---|---|---|---|
| Action menu | Three or more actions for one row | Two actions per row | How to choose |
| Radio group | Two or three visible options | `Select` | How to choose |
| Search field (combobox) | A long list | A filter with `Select` | Booking spec: the list is a handful of mentors |
| Switch | A setting that applies at once | None needed in the backlog | How to choose |
| Side panel, popover, tooltip | Detail beside a list, small explanations | A page, text on the page | How to choose |
| Tabs | Views of the same record | Separate pages | How to choose |
| Toast | Short confirmations | Plain status text. An error is never a toast | WCAG 2.2.1 |
| Success tone of `StatusBadge`, and a warning colour | Statuses | Three tones. `--status-success` exists as a token but no component uses it yet except the starter page | K3 settled for the colour on 2026-10-28; the component is not changed |
