# What to avoid

Three parts. Each point says how to recognise it, why it is a problem and what to use instead. The commands run from `packages/ui` and search `src` without tests and stories. Today they find the hits listed under each table, and nothing else.

## 1. Anti-patterns of this product

From the anti-references in `lekcja-06/referencje.md`.

| Avoid | Recognise it | Why | Use instead | Source |
|---|---|---|---|---|
| **Courses:** progress bars, badges, certificates, "modules", streaks | `role="progressbar"`, `<progress`, words "certificate", "lesson", "module" | Seekers want a blocker solved, not to learn a course. Three of four declined a subscription | A question and an answer | A02, D02 |
| **Ratings and rankings:** stars, averages, review counts, "Top mentor" | `★`, `Star`, "rating", "score". A test fails on them in `MentorRow` and `VaultAnswerView` | No scores in the product | What the mentor did and a link to public work | A03, N02 |
| **A registration wall:** "Step 1 of 4", a welcome dialog, a required profile before the first question | A multi-step form, a `Dialog` that opens on load | A fintech developer drops a booking that takes more than five minutes (D08) | The question first. Sign in with a link | A04, D08 |
| **Sales language and seniority labels:** "best experts", "grow your career", "Senior Engineer" as the only description | Search the text for these phrases | "Is this something that sells?" | A concrete task and public work | A05 |
| **Video and live conversation:** a camera icon, "Join the call", a live indicator | `Video`, `Camera`, `Mic` | Sessions are text | Text sessions | A06, N01 |
| **Social features:** follow, a feed, "invite friends", private messages outside a session | The words in the interface | "I do not want relationships, I want an answer and peace" | Nothing | A07 |

Hits today: `★` appears only in tests, a story and docs that **assert it is absent**.

## 2. The generic AI look

The signature of the typical AI start-up page (A01). The detailed list is the author's extension and is a proposal (P8).

| Avoid | Recognise it | Why | Use instead |
|---|---|---|---|
| Gradients in the background, in text and on buttons | `bg-gradient`, `linear-gradient`, `radial-gradient`, `bg-clip-text`, `background-clip: text` | "It looks like everything else" (A01) | One flat accent, `--primary` |
| Glass and blur | `backdrop-blur`, `backdrop-filter` | It is an effect, not information, and it lowers contrast | A solid surface and a hairline |
| Glow | `shadow-`, `drop-shadow`, `box-shadow`, `blur-` | It does not mark an edge for everyone (WCAG 1.4.11) | A hairline (`--border`) |
| Emoji instead of icons | An emoji character in the source | It renders differently on every system and reads as noise (P3) | An icon from the icon set, or words |
| Sparkles as the symbol of AI | `Sparkle`, `Wand`, `Stars`, `Zap` | A cliché. The AI label is words | "Generated by AI from the notes below" |
| Three identical cards with an icon | Three sibling `Card`s, each with an icon and a title | It says nothing specific | One row per fact, in words |
| Everything in pills | `rounded-full` on anything but an avatar | A large radius on every element is a mark of generic design (proposal) | The radius steps in **Shape and depth** |
| A card in a card | A `Card` inside a `Card` | Nested boxes add noise | A hairline and spacing |
| Shadow as the only separator | `shadow-` with no `border` | A shadow does not mark an edge | A hairline |
| Everything centred | `text-center` on running text | Hard to scan | Left-aligned text. Centre only a single message |

Hits today: `text-center` appears in `EmptyState`, `ErrorMessage` and `LoadingMessage` (a single message in the middle of a region), and in the button label. Everything else has no hit.

```sh
cd packages/ui
grep -rEn 'bg-gradient|linear-gradient|bg-clip-text|backdrop-blur|backdrop-filter|shadow-|drop-shadow|Sparkle|Wand|rounded-full' src \
  --include=*.tsx --include=*.ts --include=*.css | grep -v '\.stories\.\|\.test\.'
```

## 3. Implementation mistakes

| Avoid | Recognise it | Why | Use instead |
|---|---|---|---|
| A value outside the tokens | `npm run check:tokens` prints the file and the line | A change of a token must change the whole product | A semantic token (`bg-card`, `gap-group`) |
| A variant added on the side | A new `variant` or a `className` that restyles a component in one place | Two looks for one thing | Ask for the variant in the component. See **Contributing** |
| A `div` instead of a button | `<div onClick`, `<span onClick` | No keyboard, no role | `Button`, `TextLink` |
| A placeholder instead of a label | An `Input` or `Textarea` with no `Field` | It disappears when typing (WCAG 3.3.2) | `Field` |
| A status shown only by colour | A dot or a colour with no text | WCAG 1.4.1 | `StatusBadge` with words |
| A blocked button with no explanation | `disabled` on a button that the user can fix | The user does not know why | `disabledReason` |
| A toast with an error that needs action | `toast(`, `sonner`. There is no toast component | It disappears before it is read | `Alert`, `ErrorMessage`, `Field` error |
| A tooltip with information needed to act | `title=` on an element, a `Tooltip` | Not for touch or keyboard | Text on the page, a `Field` hint |

Hits today: none for the commands of rows 3 to 8. The word "toast" appears once, in a comment of `alert.tsx` that says an error is never a toast.

```sh
cd packages/ui
npm run check:tokens
grep -rEn '<(div|span)[^>]*onClick|toast\(|sonner|<(a|button|span|div)[^>]* title=' src --include=*.tsx | grep -v '\.stories\.\|\.test\.'
```
