# Usage and accessibility

The rules the interface keeps for you. Each has a source: a reference (R, A), a decision, a spec, WCAG 2.2 or WAI-ARIA. A rule without a source is marked **proposal**. The accessibility check of every story runs with `a11y.test: 'error'`. Contrast is measured from the tokens by `npm run tokens:contrast`, in both themes.

## Keyboard and focus

| Rule | Where it is kept | Source |
|---|---|---|
| Everything works with a keyboard, in the visual order | Native elements: `button`, `a`, `input`, `select`, `textarea` | WCAG 2.1.1, 2.4.3 |
| Focus is always visible: a 2 px ring with a 2 px offset, in `--ring` | Every control | WCAG 2.4.7, 1.4.11 |
| A blocked button stays in the keyboard order and is described by its reason | `Button disabledReason` | Decision 2026-10-27 |
| A dialog traps focus, closes with Escape and returns focus | `Dialog`, `ConfirmDialog` (Radix) | WAI-ARIA dialog pattern |
| After a failed submit, focus moves to the first error | `CrudForm`, `QuestionForm` | WCAG 3.3.1 |
| Ctrl or Cmd plus Enter sends the message and submits a form | `Composer`, `CrudForm`, `QuestionForm` | R02.2 (message box). Forms: proposal |
| Controls are at least 32 px high (40 px in forms and the session) | Control tokens | WCAG 2.5.8 |

## Forms and messages

| Rule | Where it is kept | Source |
|---|---|---|
| Every control has a visible label. A placeholder is an example | `Field` | WCAG 3.3.2 |
| An error is a sentence with an icon, linked to the field, and announced | `Field` (`role="alert"`, `aria-describedby`) | WCAG 3.3.1, 4.1.3 |
| An error says what to do | Content page | WCAG 3.3.3 |
| What was typed stays after any failure | Forms and `Composer` | Form pattern |
| A second submit is ignored while one runs | Forms and `Composer` | Form pattern |
| Success is reported only after the server confirmed | `onSuccess` | Form pattern |
| Required is marked on the minority of fields | `Field requirement` | Form pattern |
| A field is checked when the user leaves it after editing, not when they only tab past | `CrudForm`, `QuestionForm` | Form pattern (proposal) |

## Colour

| Rule | Where it is kept | Source |
|---|---|---|
| Text has 4.5:1 and interface parts 3:1, in both themes | `npm run tokens:contrast` | WCAG 1.4.3, 1.4.11 |
| Colour is never the only carrier of meaning: a status is words | `StatusBadge`, `BookingStatus`, `PilotCountsTable` | WCAG 1.4.1 |
| Links are underlined | `TextLink` | WCAG 1.4.1 |
| One accent, `--primary`. One main action per screen | `Button` | R01.5, proposal P2 |
| In the light theme the accent is a fill only. Links and focus use the text colour | Light theme tokens | Decision (a), 2026-10-27 |
| Success has its own colour, `--status-success`, used with words. A warning colour is not defined | `StatusBadge` still has three tones | Decision 2026-10-28 (settles K3) |

## Motion and content

| Rule | Where it is kept | Source |
|---|---|---|
| Feedback takes 100 to 150 ms and is 0 ms with reduced motion | Motion tokens | WCAG 2.3.3, proposal for the values |
| No endless animation, no pulse | `Skeleton` is still | A01, WCAG 2.2.2 |
| A change of state is also in words | Messages and statuses | WCAG 1.4.1 |
| New messages are announced politely and nothing is re-read | `SessionThread` (`aria-live="polite"`) | WAI-ARIA, WCAG 4.1.3 |
| No ticking countdown: a time is stated as text from the server's time | `SessionWindow`, `ReviewItem` | WCAG 4.1.3, proposal |
| Text from users and the AI is never rendered as markup, and AI text has no links | `MarkdownView`, `MessageItem`, `VaultAnswerView` | Security, vault spec |
| Headings do not skip a level | `headingLevel` on `MentorRow`, `ReviewItem` | WCAG 1.3.1 |

## Layout across widths

| Rule | Where it is kept | Source |
|---|---|---|
| Sizes are in `rem`, so zoom works | Typography tokens | WCAG 1.4.4 |
| The page reflows to 320 px without a sideways scroll. Tables and code scroll inside their container | `Table`, `MarkdownView`, `MessageItem` | WCAG 1.4.10 |
| Lists and tables are at most 72 rem wide. The session is one column of at most 44 rem | `max-w-content`, `max-w-session` | R02.1. Values: proposal |
| Running text is at most 65 characters wide | `--measure-text` | WCAG 1.4.8 guidance, proposal |
| Lists are dense, the session is roomy | `p-panel-compact`, `p-panel-roomy` | K1 |

**Not verified:** the widths 320, 768 and 1440 px, both themes and the keyboard have not been checked in a browser in this environment. The rules above are built into the components and checked in jsdom, but not seen.

## Rules of the product that the interface keeps

| Rule | Where it is kept | Source |
|---|---|---|
| The price comes before the question | `PriceNotice`, `QuestionForm` | R04 |
| The mentor sees the question before accepting | `BookingRow` | R05 |
| The mentor loses the question after a decline or an expiry | `BookingRow` | Booking spec, Grill 8 |
| No ratings, no scores, no "Top mentor": a link to public work instead | `MentorRow`, `VaultAnswerView` (a test fails on a star or a score) | N02 |
| Where the money stands is written | `BookingStatus`, `VaultAnswerView` | Booking and vault specs |
| The mentor agrees to the notice every time they publish | `PublishNoticePanel` | D09 |
| A vault answer is labelled as AI-generated and lists "Mentor name, note title" | `VaultAnswerView` | D10, D14 |
| One rejection rejects the whole answer, and the buttons say so | `ReviewItem` | Vault spec, Q4 |
| Test payments are not counted | `PilotCountsTable` | Booking spec, Grill 9 |
| Rows are divided by a hairline, not boxed in cards | List components | R01.1 |
| Column headers are clear | `Table`, `DataTable` | R01.3 |
| The conversation is in the centre of one column | `SessionThread` | R02.1 |
| Author and time are with every message | `MessageItem` | R02.3 |
