# ConfirmDialog

## 1. What it is for

A confirm dialog asks the user to approve an action that is final or costs something, before it happens.

<Canvas of={ConfirmDialogStories.Destructive} />

## 2. When to use it

- Take down a published note (R03).
- Cancel a paid vault answer or a booking.
- Send a question and pay, when the amount must be re-stated.

## 3. When not to use it, and what to use instead

| Situation | Use instead | Why |
|---|---|---|
| A reversible action | Do it, and offer an undo | A question on every click trains users to click through it |
| Collecting input | `Dialog` | A confirm dialog only asks yes or no |
| An error | `Alert` | Not a question |
| A routine save | Nothing | Save is not a question |

## 4. Anatomy

1. **Title**: the question, naming the object.
2. **Description** (optional): what happens, and whether it can be undone.
3. **Error** (only on failure): an alert inside the dialog.
4. **Cancel**: the way out, easy to find.
5. **Confirm**: the action as a verb and an object.

## 5. Variants

| Tone | Choose it when | Confirm button |
|---|---|---|
| `destructive` | The action deletes, cancels or cannot be undone | `destructive` |
| `default` | A final step that is not destructive, such as paying | `default` |

## 6. States

| State | What the user sees | Source |
|---|---|---|
| Open | The question, the way out, the action. Focus is on the way out | WAI-ARIA APG alert dialog |
| Pending (`pending`) | Both buttons are blocked, the confirm label may change ("Taking down…"), so it cannot be sent twice | Decision 2026-10-27 |
| Error (`error`) | An alert inside the dialog says why it failed. The dialog stays open so the user can retry | WCAG 3.3.1 |
| Closed | Nothing. The caller closes it after the work succeeded | |
| Hover, focus, pressed | Belong to the two buttons | |

## 7. Behavior and accessibility

- **Role:** `alertdialog`, named by the title, described by the description.
- **Focus:** starts on **Cancel**, the least destructive action. `Tab` stays inside. `Escape` asks to close.
- **No accidental dismissal:** there is no close icon and a click on the scrim does not confirm. The user must choose.
- **Confirming does not close it by itself.** `onConfirm` runs, and the caller closes the dialog (`onOpenChange(false)`) when the work succeeded. That is how a failure can stay on screen.
- **Return focus:** focus goes back to the control that opened the dialog.

## 8. Content

- **Title:** the question with the object's name: `Take down "Ingress upgrade notes"?`. Never "Are you sure?".
- **Description:** the consequence, and whether it can be undone: "Answers already sold stay."
- **Confirm label:** a verb and an object: "Take down note". Never "OK" or "Yes".
- **Cancel label:** "Cancel", or a statement of keeping: "Keep the answer".
- **Long titles:** wrap onto several lines.

<Canvas of={ConfirmDialogStories.LongTitleNarrow} />

## 9. Responsiveness

At 320 px the buttons stack, with the action on top and the way out below it. At 768 px and above they sit in one row with the action on the right.

## 11. Code

```tsx
import { ConfirmDialog } from '@devmentor/ui';

<ConfirmDialog
  open={open}
  onOpenChange={setOpen}
  title={`Take down "${note.title}"?`}
  description="Answers already sold stay."
  confirmLabel="Take down note"
  tone="destructive"
  pending={pending}
  error={error}
  onConfirm={takeDown}
/>
```

## 12. Do and don't

| | Example | Why |
|---|---|---|
| Do | Title `Take down "Ingress upgrade notes"?`, button "Take down note" | The question and the button both name the object and the action |
| Don't | Title "Are you sure?", buttons "Yes" and "No" | The user must read the page behind the dialog to know what "Yes" does |
| Do | Close the dialog from `onConfirm` after the request succeeded | A failure stays visible and can be retried |
| Don't | Close it immediately and report a failure later | The user believes it worked |

## 13. Related

- **Confused with:** `Dialog` (collects input) and `Alert` (a message).
- **Used in patterns:** Confirm destructive action (take down, cancel), Paid action flow (final step).
