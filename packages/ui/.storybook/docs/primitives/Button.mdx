# Button

## 1. What it is for

A button starts an action the user chooses to take: pay for a session, send a question, accept a booking.

<Canvas of={ButtonStories.Playground} />

## 2. When to use it

- Pay for a 25-minute session or a vault answer (the one main action of that screen).
- Send a question to a mentor; send a message in the session.
- Accept or decline a booking; approve or reject a vault answer preview.
- Publish a note after the notice and the consent.

Use at most **one** `default` button per screen. It is the one accent action (R01.5, P2).

## 3. When not to use it, and what to use instead

| Situation | Use instead | Why |
|---|---|---|
| Going to another page | `TextLink` | A link goes somewhere, a button does something (WAI-ARIA APG) |
| Turning a choice on or off, or agreeing to terms | `Checkbox` | The state must be visible and reachable by keyboard |
| An action that cannot be undone | A confirmation dialog first (`ConfirmDialog`, next batch), then a `destructive` button | The user must see what will be lost |
| Showing status | `StatusBadge` (next batch) | A status is not an action |

## 4. Anatomy

1. **Label** (required): a verb and an object.
2. **Leading icon** (optional): a lucide icon, `size-4`, `aria-hidden`.
3. **Reason** (optional, only when blocked): the text under the button that explains why it is unavailable.

## 5. Variants and sizes

| Variant | Choose it when | Source |
|---|---|---|
| `default` | It is the one main action of the screen | R01.5, P2 |
| `outline` | A secondary action next to the main one | R01.1 (thin outline) |
| `ghost` | A quiet, tertiary action such as "Cancel" | K1 (dense lists) |
| `destructive` | The action deletes, cancels or cannot be undone | WCAG 1.4.3 |
| `secondary`, `link` | **Do not choose.** Kept so existing code keeps working: use `outline` and `TextLink` | Decision 2026-10-27 |

| Size | Height | Use it for |
|---|---|---|
| `default` | at least 40 px | Forms and the session view |
| `sm` | at least 32 px | List rows, filters, table actions (K1) |
| `icon` | 40 px square | A button with only an icon. It needs `aria-label` |

## 6. States

Hover and focus cannot show on a static page, so the preview uses the same styles through a documentation-only attribute.

<Canvas of={ButtonStories.States} />

| State | What the user sees | Source |
|---|---|---|
| Default | The variant's fill or outline | |
| Hover | The fill at 90% (a little paler or darker, depending on the theme). **`destructive` keeps its fill and underlines the label instead**: its fill at 90% in the dark theme has 3.95:1 with its text | Decision 2026-10-27. Exception 2026-10-28: WCAG 1.4.3, 1.4.1 |
| Focus | A solid 2 px ring in `--ring` with a 2 px gap in the page colour. Never removed | WCAG 2.4.7, 1.4.11 |
| Pressed | No separate style: the hover look stays while the button is pressed. The action runs on release | Proposal |
| Loading | No built-in spinner. Change the label to a progressive verb ("Sending…") and block the button with `disabled`. The reason is obvious from the label | Proposal |
| Blocked, user can fix it | Muted fill and muted text. Use `disabledReason`: the button stays reachable by keyboard and the reason is written under it | Decision 2026-10-27 |
| Blocked, in progress | `disabled` (not in keyboard order). Only when the label already says why | Decision 2026-10-27 |
| Error | Not a button state. A failed action is reported by the form (Field, Alert), not by the button | WCAG 3.3.1 |

## 7. Behavior and accessibility

- **Keyboard:** `Tab` reaches it, `Enter` and `Space` activate it (WAI-ARIA APG button pattern).
- **Focus order:** follows the page order. A blocked button with a reason stays in the order.
- **ARIA:** blocked with a reason sets `aria-disabled="true"` and `aria-describedby` pointing at the reason. An icon-only button needs `aria-label`.
- **Screen reader:** announces the name, "button", the dimmed state and then the reason.
- **Target size:** at least 32 px, above the 24 × 24 px minimum (WCAG 2.5.8).
- **Colour:** the label is always text, so state is never shown by colour alone (WCAG 1.4.1).

## 8. Content

- **Label:** a verb and an object: "Pay 25 EUR", "Send question", "Cancel booking". Never "OK", "Submit" or "Yes".
- **Length:** up to about 25 characters. A longer label wraps onto a second line instead of overflowing; the button grows taller.
- **Numbers:** write the amount with its currency ("25 EUR").
- **Longer languages:** the product UI is English, but a translation up to 40% longer still fits because the label wraps.

## 9. Responsiveness

| Width | Behaviour |
|---|---|
| 320 px | In forms the main button takes the full width (`className="w-full"`) |
| 768 px | Natural width, buttons sit in one row |
| 1440 px | Natural width. The main button is still one per screen |

## 11. Code

```tsx
import { Button } from '@devmentor/ui';

<Button>Pay 25 EUR</Button>
```

```tsx
// Typical: pay for a session. The reason tells the user how to unblock it.
<Button disabledReason={question ? undefined : 'Write your question to continue'} onClick={pay}>
  Pay 25 EUR
</Button>
```

## 13. Related

- **Confused with:** `TextLink` (navigation) and `Checkbox` (a choice).
- **Used in patterns:** Form (submit and cancel), Paid action flow (price, pay), Review queue (approve, reject).
