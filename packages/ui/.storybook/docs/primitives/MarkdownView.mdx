# MarkdownView

## 1. What it is for

MarkdownView shows text written in markdown by a mentor, a seeker or the AI, as safe, readable content.

<Canvas of={MarkdownViewStories.Playground} />

## 2. When to use it

- A mentor's note, in the editor preview and wherever it is shown.
- A seeker's question that can contain code or yaml.
- A message in the session, so a pasted code block stays a code block (R01.2).
- An AI-generated vault answer (with `linkPolicy="none"`).

## 3. When not to use it, and what to use instead

| Situation | Use instead | Why |
|---|---|---|
| A short label or a status | Plain text or `StatusBadge` | Markdown adds nothing |
| Trusted layout written by the team | Components | MarkdownView limits what content can do |
| Rich HTML from outside | Do not render it | Raw HTML is never rendered here |

## 4. Anatomy

1. **Content**: paragraphs, lists, quotes, headings, links, inline code and fenced code blocks.
2. Nothing else. There are **no images, no raw HTML and no scripts**.

## 5. Variants

| Link policy | Choose it when | Source |
|---|---|---|
| `safe` (default) | A human wrote the text. `http(s)` and `mailto` links are real links with `rel="noopener noreferrer nofollow"` | OWASP output encoding |
| `none` | The AI wrote the text. A link is shown as plain text, so an injected link cannot be clicked | Proposal (prompt injection) |

## 6. States

MarkdownView only displays what it is given.

| State | What the user sees | Source |
|---|---|---|
| Content | Formatted text. Code is in the code font on the muted surface | R01.2 |
| Hostile content | Raw HTML, `javascript:` links and images are dropped or shown as text, never executed | Security |
| Empty | Nothing. The caller shows an empty state | |
| Loading, error | Not its states. The caller shows `Skeleton` or `ErrorMessage` | |
| Hover, focus, pressed | Belong to links inside the text | WCAG 2.4.7 |

<Canvas of={MarkdownViewStories.HostileContentIsInert} />

## 7. Behavior and accessibility

- **Links** are underlined and have a focus ring, like `TextLink`.
- **Headings are pushed down two levels** (`#` becomes `h3`, `##` becomes `h4`), so an author cannot break the page outline.
- **Code blocks scroll sideways** inside their own box and keep their whitespace. They can be reached with a keyboard because the box is scrollable.
- **No images:** nothing is fetched from a third party when the text is opened (privacy).

<Canvas of={MarkdownViewStories.CodeStaysCode} />

## 8. Content

- **Authors:** write short paragraphs, name the command or the file in code, put long output in a code block.
- **Do not rely on formatting for meaning** (WCAG 1.3.1): say "Warning:" in words rather than only bolding a line.
- **AI text** is labelled as AI-generated by the screen that shows it (see VaultAnswerView).

<Canvas of={MarkdownViewStories.AiAnswerWithoutLinks} />

## 9. Responsiveness

Text wraps at the container width. A code block scrolls sideways at 320 px instead of widening the page. Cap running text at the reading measure (65 characters) on wide screens.

## 11. Code

```tsx
import { MarkdownView } from '@devmentor/ui';

<MarkdownView source={note.body} />
```

```tsx
// Typical: an AI-generated answer. Links are shown as text.
<MarkdownView source={answer.text} linkPolicy="none" />
```

## 12. Do and don't

| | Example | Why |
|---|---|---|
| Do | `linkPolicy="none"` for text the AI wrote | An injected link must not become clickable |
| Don't | Set `dangerouslySetInnerHTML` with markdown output | It bypasses every protection here |
| Do | Show a pasted yaml block in a code block | Code stays code (R01.2) |
| Don't | Render the author's headings as page headings | The page outline would break |
