# Field

## 1. What it is for

A field gives a form control its visible name, its help text and its error message, and connects all three to the control for assistive technology.

<Canvas of={FieldStories.Playground} />

## 2. When to use it

- Every control in a form: e-mail on the sign-in form, the question before paying, the title of a note.
- A consent checkbox (`orientation="inline"`).
- A single filter that needs a visible name.

## 3. When not to use it, and what to use instead

| Situation | Use instead | Why |
|---|---|---|
| A search box in a toolbar where the label would be redundant | The control with `aria-label` | The name still exists, it is just not drawn |
| A group of related choices | A `fieldset` with a `legend` (not built yet, see What is missing) | A group needs one name |
| A message about the whole form | `Alert` | An error that is not about one field |

## 4. Anatomy

1. **Label** (required): the visible name. Placeholders are examples, never names.
2. **Requirement mark** (optional): "(required)" or "(optional)", written as text.
3. **Hint** (optional): help shown under the label, before the control.
4. **Control** (required, exactly one): `Input`, `Textarea`, `Select` or `Checkbox`.
5. **Error** (appears only when needed): an icon and a sentence.

## 5. Variants

| Orientation | Use it for | Source |
|---|---|---|
| `stacked` (default) | Text controls: label above, control below | R01.3 (clear labels) |
| `inline` | A checkbox: control first, label beside it | WAI-ARIA APG checkbox pattern |

## 6. States

<Canvas of={FieldStories.States} />

| State | What the user sees | Source |
|---|---|---|
| Default | Label and control | |
| With a hint | Help text under the label, linked with `aria-describedby` | WCAG 3.3.2 |
| Required, optional | "(required)" or "(optional)" next to the label. Mark the minority: if most fields are required, mark the optional ones | WCAG 3.3.2, proposal |
| Focus | The control's own focus ring | WCAG 2.4.7 |
| Error | `aria-invalid`, a destructive outline on the control, and an icon plus a sentence under it. Announced when it appears | WCAG 1.4.1, 3.3.1, 4.1.3 |
| Blocked | The control is disabled. The hint says why and when it unlocks | Decision 2026-10-27 |
| Success | Nothing is drawn. A valid field looks like a normal one. The success colour is undecided (K3) | Proposal |
| Loading | Not a field state. A form that loads shows a skeleton | |

## 7. Behavior and accessibility

- **Label:** a real `<label for>` connects to the control, so a click on the label focuses it.
- **Description:** hint and error ids are joined in `aria-describedby`. A screen reader reads the label, then the hint and the error.
- **Invalid:** `aria-invalid="true"` appears with the error. The error is `role="alert"`, so it is announced as soon as it appears.
- **Keep it:** the error stays until the cause is fixed.
- **After a failed submit:** focus goes to the first field with an error (the Form pattern does this).
- **A child that sets its own `aria-describedby`** overrides the one Field passes. Do not set it by hand.

## 8. Content

- **Label:** a noun, short: "Email", "Your question". No colon, no "Enter your".
- **Hint:** what helps the user succeed: "Paste the error and what you already tried." Not a repeat of the label.
- **Error:** what is wrong and what to do: "Enter an address like ada@devmentor.local". Never "Invalid input".
- **Requirement:** a word in the label, never only an asterisk or a colour.

<Canvas of={FieldStories.LongTextNarrow} />

## 9. Responsiveness

Stacked at every width, so nothing moves at 320 px. An inline checkbox keeps the box at its size and wraps the label beside it. Long label, hint and error wrap and are never cut.

## 11. Code

```tsx
import { Field, Input } from '@devmentor/ui';

<Field label="Email">
  <Input type="email" />
</Field>
```

```tsx
// Typical: the question before paying, with a hint and a server-side error.
<Field
  label="Your question"
  requirement="required"
  hint="Paste the error and what you already tried. Do not paste secrets."
  error={errors.question}
>
  <Textarea value={question} onChange={(event) => setQuestion(event.target.value)} />
</Field>
```

## 12. Do and don't

<DoDont
  doExample={<div className="w-64"><Field label="Email"><Input placeholder="ada@devmentor.local" /></Field></div>}
  doWhy="The field is named by a label. The placeholder is only an example."
  dontExample={<div className="w-64"><Input aria-label="Email" placeholder="Email" /></div>}
  dontWhy="A placeholder that is the name disappears as soon as the user types."
/>
<DoDont
  doExample={<div className="w-64"><Field label="Email" error="Enter an address like ada@devmentor.local"><Input defaultValue="ada@" /></Field></div>}
  doWhy="The error is a sentence with an icon that says what to do."
  dontExample={<div className="w-64"><Input aria-label="Email" aria-invalid="true" defaultValue="ada@" /></div>}
  dontWhy="A red outline alone does not tell everyone what is wrong (WCAG 1.4.1)."
/>
