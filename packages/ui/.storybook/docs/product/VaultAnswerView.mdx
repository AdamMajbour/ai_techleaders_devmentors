# VaultAnswerView

## 1. What it is for

What the seeker sees of a vault answer in every state: being written, waiting for the mentors, released with its sources, or ended with where the money stands.

<Canvas of={VaultAnswerViewStories.Released} />

## 2. When to use it

- The page of one vault answer (E02-S03).

## 3. When not to use it, and what to use instead

| Situation | Use instead | Why |
|---|---|---|
| The answer a mentor reviews | `ReviewItem` | It has the decision beside it |
| A written answer of a mentor | `MarkdownView` | Not generated, no label |
| The payment return | Patterns: Paid action flow | It comes before this page |

## 4. Anatomy

1. **The seeker's question.**
2. **The state**, announced politely.
3. **When released:** the permanent label, the answer (`MarkdownView` without links) and the list "Notes used".
4. **When ended without an answer:** one sentence and the refund line.

## 5. Variants

| Status | The seeker reads |
|---|---|
| `generating` | "Writing your answer…" and that they can leave the page |
| `pending_preview` | "Waiting for the mentors whose notes were used. They read the answer first, up to 120 minutes. You are refunded if they do not approve." |
| `released` | The label, the answer, the notes used |
| `rejected` | "The mentors whose notes were used did not approve this answer. You are refunded." |
| `expired` | "The mentors did not answer in time. You are refunded." |
| `generation_failed` | `unanswerable`: "The notes do not cover your question, so no answer was written. Nothing was kept. You are refunded." Any other reason: "We could not write the answer. You are refunded." |
| `cancelled` | "This answer was cancelled. You are refunded." |

## 6. States

| State | What the user sees | Source |
|---|---|---|
| Each status above | Its sentence. The wording is **proposal** where the spec gives only the idea | Vault spec, answer states |
| Refund `pending_approval`, `processing`, `refunded` | The refund line under the sentence | Vault spec, booking spec |
| A rejection | The seeker is told only that it was not approved. The mentors' reasons are never shown | Vault spec |
| Loading, not found, load failed | Belong to the page: see "E02 Notes and vault" > Answer | |

## 7. Behavior and accessibility

- **Permanent label:** "Generated by AI from the notes below. Not written by the mentor." It comes before the text and cannot be turned off (D10, D14).
- **No links in generated text.** A link is shown as plain text, so an injected link cannot lead the seeker anywhere.
- **No rating** and no link to the note itself in the pilot (N02, vault spec).
- **Polite announcements:** a change of state is read when the user is idle.
- **Citations are snapshots:** the mentor's name and the note's title are shown as they were when the answer was written.

<Canvas of={VaultAnswerViewStories.LinkInGeneratedTextIsPlain} />

## 8. Content

- **Every ended state says "You are refunded"** and the refund line says where the money really stands.
- **The unanswerable case** says the notes did not cover the question and that nothing was kept.

## 9. Responsiveness

One column. At 320 px a long question, a long note title and many citations wrap.

## 11. Code

```tsx
import { VaultAnswerView } from '@devmentor/ui';

<VaultAnswerView
  question={answer.question}
  status={answer.status}
  answerText={answer.answerText}
  citations={answer.citations}
  failureReason={answer.failureReason}
  refund={answer.refundStatus}
  previewMinutes={120}
/>
```

## 12. Do and don't

| | Example | Why |
|---|---|---|
| Do | "Mentor name, note title" for each source | The seeker can see where it came from (D10, D14) |
| Don't | "Answered by Ada" | The AI wrote it, not the mentor |
| Do | Say the notes did not cover the question | An honest outcome, with a refund |
| Don't | Show a confidence score or stars | N02, and the product has no score |
